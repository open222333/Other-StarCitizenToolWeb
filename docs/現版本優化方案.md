# 現版本優化方案

日期：2026-11-15，對應 commit 52eced8（CCU 價格資料庫）
依據：《專案優化建議.md》的檢查結果，加上 11-13 之後新增的功能（玩家頁分頁重整、戰術小隊、後台設定分頁、CCU／Open Hangar）。
章節代號（R1、D5…）對應《專案優化建議.md》。

排序原則：先做「部署上會出事」的，再驗證剛上線的功能，再做效能和整理，最後才加新畫面。

## 第 0 階段：部署設定（半天～1 天）

只改設定檔，不動功能，做完重建容器即可。

| # | 項目 | 做法 | 章節 |
|---|---|---|---|
| 0-1 | 玩家站 gzip | `conf/nginx-web/default.conf` 加 `gzip on`、`gzip_proxied any`、`gzip_types`（JS、CSS、JSON、SVG），API 回應一起壓 | R1、N3 |
| 0-2 | gunicorn worker 數 | `conf/config.ini.default` 固定 `WORKERS=2`、`WORKER_CLASS=gthread`、`THREADS=4` | R3 |
| 0-3 | Celery 行程數 | `CELERY_WORKER_CONCURRENCY` 預設改 2 | R5 |
| 0-4 | 保存期限 | `sync_runs` 加 90 天 TTL 索引；`inventory_log` 先決定保留多久再加 | R6 |
| 0-5 | 容器 log 上限 | 每個服務加 `logging` 的 `max-size`、`max-file` | N4 |
| 0-6 | Bootstrap JS 重複 | 拿掉 `main.js` 的 `bootstrap.bundle.min.js`，點過後台對話框確認 | N1 |

完成標準：玩家頁主 JS 回應有 `Content-Encoding: gzip`；API 容器在 4 核主機上不超過 256 MB。

## 第 1 階段：驗證剛上線的 CCU 資料（1 天，要在 Docker 環境做）

開發環境連不到 RSI 和 Open Hangar，兩個同步項目都只用假資料測過。

| # | 項目 | 做法 |
|---|---|---|
| 1-1 | RSI 商店同步 | 手動跑「CCU」，確認 `rsi_ships` 約 250 艘、`ccu_offers` 有 ship／ccu 兩種；失敗就依錯誤訊息修 `src/rsi_store.py` |
| 1-2 | Open Hangar 同步 | 手動跑「Open Hangar 歷史」，確認 `ship_sale_history` 對到 `rsi_id` 的比例 |
| 1-3 | 對不到的船 | 列出兩邊名稱對不到的（例如 `Khartu-Al` 大小寫、`MISC Freelancer` 前綴），補比對規則 |
| 1-4 | U 代碼 | 拿幾艘 U 期間的船對照 RSI 公告，確認意義後改 `SALE_TYPES` 的標籤 |
| 1-5 | 販售活動 | 取得 `/api/hangar/calendar` 格式後，新增「販售活動」資料表，把每段上架期間對到 IAE、Invictus 等活動 |

完成標準：兩個項目在排程頁連續三天成功；對到 RSI 船 id 的比例 ≥ 90%。
