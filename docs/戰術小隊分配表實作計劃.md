# 戰術小隊分配表：實作計劃

日期：2026-11-13
狀態：第 1～3 階段已實作（2026-11-13）。第 4 階段（後台管理列表、拖曳排序、「誰有這艘船」提示）還沒做。

實作跟計劃不同的地方：

- 不是獨立主分頁，放在「工具箱 › 戰術小隊」（`?tab=toolbox&sub=squads`，下層分頁標 `member: true`）。
- 列表與編輯合在 `components/SquadBoards.vue`；「加入人員」直接用 `AutocompleteField`（候選最後一項是「加為未註冊人員」），沒有另外拆 `SquadMemberInput.vue`。
- 建議乘員數用載具主檔的 `crew_max`，不是 `ship_loadout_master.crew`。
- 開著的表記在網址 `&board=<id>`。

## 需求與已確認的決定

需求：建立戰術小隊分配表，可以加入艦船、選玩家、加入沒有註冊網站的人員，未登入也能看分配頁面。

| 問題 | 決定 |
|---|---|
| 誰能建立和編輯 | 登入的玩家都能建立；只有建立者和後台管理員能編輯、刪除；其他登入玩家只能看 |
| 未登入怎麼看 | 分享連結：每張表一條帶隨機碼的連結，知道連結就能看（唯讀）；建立者可以關閉或重新產生 |
| 表格層級 | 小隊 → 艦船 → 人員；小隊裡也可以有不在船上的人員（例如地面隊） |

## 畫面

### 玩家頁新分頁「小隊分配」（`?tab=squads`）

放在「艦隊」後面。兩個畫面：

**列表**（表格樣式跟艦隊、藍圖一致）

- 欄位：名稱、行動時間、小隊數、艦船數、人數、建立者、更新時間。
- 工具列：「新增分配表」。
- 每列按鈕：「開啟」；自己的表多「複製」「刪除」。
- 所有登入玩家都看得到全部的表。

**編輯**（開啟一張表）

- 表頭：名稱、行動時間（選填）、備註（選填）。
- 分享區：開關「分享連結」、複製連結、重新產生連結。
- 每個小隊一張卡片：
  - 小隊名稱、隊長（從這個小隊的人員裡選）、備註。
  - 「加入艦船」：用現有的 `ShipPicker` 選船，自己機庫的船排前面；可填識別名稱（例如「一號機」）。
  - 每艘船底下列人員，每人一列：人員、職位、移除。
  - 「不在船上」區塊，放沒有分配到船的人員。
- 「加入人員」的輸入框（一個欄位兩種用法）：
  - 打字時出現玩家候選（用現有的 `/player/search`），選一個就綁定該玩家。
  - 不選候選、直接按 Enter，就當成「未註冊人員」，只記名字，名字後面標「未註冊」。
- 職位：下拉＋可自填。預設選項：駕駛、副駕駛、砲手、工程師、醫療、陸戰、其他。
- 同一個玩家在同一張表出現兩次時，兩處都標「重複」（不擋，有人可能真的要兼任）。
- 船的建議乘員數（`ship_loadout_master.crew`）顯示成「3 / 6 人」，超過時標紅。
- 排序：小隊、艦船、人員都用上下箭頭調整順序（跟 AI 設定的供應商排序一樣），第一版不做拖曳。
- 手機：小隊卡片直向堆疊，人員列用現有的 `sf-stack`。
- 非建立者開啟時是唯讀，沒有任何編輯按鈕。

### 公開頁（不用登入）

- 網址：`/player/squad/<分享碼>`。
- 內容：名稱、行動時間、備註、各小隊的艦船與人員、職位。唯讀，沒有編輯按鈕。
- 版面跟編輯畫面的唯讀模式共用同一個元件。
- 分享碼不存在或已關閉時顯示「這個連結已失效」。
- 頁面加 `<meta name="robots" content="noindex">`，避免被搜尋引擎收錄。

**公開頁會顯示哪些個人資料**

只顯示玩家的暱稱（沒有暱稱才顯示遊戲 ID）和未註冊人員的名字。不顯示真實名稱、Discord、持有的船或物品。分享開關旁邊要寫明「知道連結的人不用登入就能看到這張表的人員名單」。

## 資料

新資料表 `squad_boards`，一張表一筆文件（小隊、船、人員都嵌在裡面，一次讀寫整張）：

```
{
  _id: ObjectId,
  title: "週六 Idris 攻堅",
  event_at: "2026-11-21T20:00",      // 選填
  note: "",
  owner_scid: "Pilot_abcd",          // 建立者的遊戲 ID
  share_token: "k3J9...",            // 22 字元隨機碼；null＝沒開分享
  squads: [
    {
      id: "s1", name: "Alpha", note: "", leader: "m3",   // leader＝人員 id
      ships: [
        { id: "v1", vehicle_id: "<ship uuid>", vehicle_name: "RSI Perseus", label: "一號機",
          crew: [ { id: "m1", scid: "Pilot_abcd", name: "星際旅人", role: "駕駛" },
                  { id: "m2", scid: null, name: "路人甲", role: "砲手" } ] }   // scid 為 null＝未註冊
      ],
      members: [ { id: "m3", scid: "...", name: "...", role: "陸戰" } ]       // 不在船上
    }
  ],
  rev: 7,                            // 每次儲存加 1，用來擋同時編輯
  created_at, updated_at, updated_by
}
```

說明：

- 人員存 `scid` 加上當時的顯示名稱 `name`。讀取時用 `scid` 重新查暱稱，玩家改名後會跟著更新；玩家被移除後退回存下來的名字。
- 船存 `vehicle_id` 加上當時的船名，船從主檔下架後還是顯示得出來。
- 索引：`share_token`（unique、sparse）、`owner_scid`、`updated_at`。
- 上限（後端驗證）：每位玩家 50 張表、每張表 20 個小隊、每個小隊 30 艘船、每張表 300 人；名稱 60 字、備註 500 字、人名與職位各 40 字。

## API

都放在現有的 `/player` 前綴底下，nginx 和 vite 的 API 前綴清單不用改。

| 方法 | 路徑 | 權限 | 說明 |
|---|---|---|---|
| GET | `/player/squads` | 登入玩家 | 列表（不含小隊內容，只有統計數字） |
| POST | `/player/squads` | 登入玩家 | 新增；可帶 `copy_from` 複製另一張 |
| GET | `/player/squads/<id>` | 登入玩家 | 一張表的完整內容，附 `can_edit` |
| PUT | `/player/squads/<id>` | 建立者 | 整張儲存；要帶 `rev`，跟資料庫不一樣回 409 |
| DELETE | `/player/squads/<id>` | 建立者 | 刪除 |
| POST | `/player/squads/<id>/share` | 建立者 | `{enabled: true/false, regenerate: true/false}`，回分享碼 |
| GET | `/player/squads/shared/<token>` | **不用登入** | 公開頁的資料；只回公開欄位 |

後台管理員的編輯、刪除：在後台「玩家」底下加一個簡單的列表頁，走 `admin_api('admin', 'operator')` 的 `/player/squads/admin...` 端點。可以放到第二階段。

注意事項：

- 公開端點要加流量限制（例如每個 IP 每分鐘 60 次），分享碼用 `secrets.token_urlsafe(16)`，猜不到。
- 公開端點的回應用白名單組出來（只挑要給的欄位），不要從完整文件刪欄位，避免之後加欄位時不小心外洩。
- `tests/test_permissions.py` 的 `UNGUARDED_ALLOWLIST` 要加上公開端點並註明原因，其他端點掛 `player_required`。
- 寫入都記一筆操作紀錄（`Log.create`）。
- 儲存時每個 `scid` 都要查得到玩家，查不到的回 400（避免前端傳假的 ID）。

## 測試

`tests/test_squad.py`：

- 新增、讀取、儲存、刪除、複製。
- 非建立者儲存、刪除、改分享設定都回 403；其他玩家讀取成功且 `can_edit` 是 false。
- `rev` 不對回 409。
- 各項上限、欄位長度、不存在的 `scid`、不存在的船回 400。
- 分享：開啟後公開端點讀得到；關閉後 404；重新產生後舊碼 404。
- 公開端點的回應不含 `owner_scid` 以外的個人欄位（逐欄位比對白名單）。
- 玩家改暱稱後，讀取到的名字跟著變；玩家被移除後顯示存下來的名字。

前端：`utils/squadBoard.js` 用 node 直接跑；畫面用現有的 Playwright 截圖腳本檢查桌機、手機、公開頁。

## 還沒決定、實作前想確認的三件事

1. **同時編輯**：計劃用 `rev` 擋，後存的人會看到「已經被別人改過，請重新載入」。只有建立者能編輯，所以實際上只會發生在同一個人開兩個視窗，這樣處理應該夠。
2. **未登入的人能不能回報出席**：這份計劃沒有做。公開頁純唯讀。
3. **表要不要區分「公會內都看得到」和「只有自己看得到」**：計劃是登入玩家都看得到全部的表。如果需要草稿不公開，可以加一個「草稿」開關，工作量很小。
