登入 / 帳號

後台使用 JWT Token 認證，Token 預設有效期為 8 小時。

  1. 開啟後台網址 /admin/，輸入帳號與密碼後點擊「登入」。
  2. 登入成功後 Token 自動存入瀏覽器 localStorage，有效期內重新整理不需重新登入。
  3. Token 過期後會自動導回登入頁，重新輸入帳密即可。
  4. 點擊右上角「登出」可立即清除 Token。
首次啟動：執行 python run.py 時系統自動建立預設管理員帳號 admin（密碼：admin），請於登入後立即修改密碼。
預設帳密僅供初始設定使用，正式上線前請務必更換為強密碼。

使用者管理

後台側欄 → 使用者管理（需 admin 角色）。

新增使用者

  1. 點擊右上角「＋ 新增使用者」按鈕。
  2. 填入帳號、密碼，並選擇角色（管理員 / 操作員 / 檢視者）。
  3. 再次輸入密碼確認後，點擊「儲存」。

編輯使用者

  1. 在使用者列表中點擊對應的「 編輯」按鈕。
  2. 可修改角色或重設密碼（密碼欄位留空則不變更）。
  3. 點擊「儲存」完成修改。
帳號名稱建立後不可修改；若需更換帳號名稱，請新增帳號後刪除舊帳號。

刪除使用者

  1. 點擊「」刪除按鈕。
  2. 確認彈窗後執行刪除，操作不可復原。
自己的帳號無法刪除，以防止意外失去登入權限。請至少保留一個 admin 帳號。

API — 認證 /auth

所有需要身份驗證的 API 皆須在 HTTP Header 帶入 JWT Token：

Authorization: Bearer <your_token>
Rate Limit：/auth/login 每個 IP 限制 10 次 / 分鐘；/auth/refresh 限制 30 次 / 分鐘。超過限制回傳 429 Too Many Requests。

POST  /auth/login

使用帳號密碼取得 JWT Token。

Request Body（JSON）：

{
  "username": "admin",
  "password": "admin"
}

成功回應：

{
  "success": true,
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "role": "admin"
}
HTTP 狀態說明
200登入成功，回傳 Token 與角色
401帳號或密碼錯誤

API — 使用者 /user

使用者 CRUD API，需攜帶 JWT Token，且需 admin 角色（讀取除外）。

GET  /user/ — 取得所有使用者

# 需要 admin 角色
GET /user/
Authorization: Bearer <token>

成功回應：

{
  "success": true,
  "data": [
    { "_id": "...", "username": "admin", "role": "admin", "created_at": "..." }
  ]
}

POST  /user/ — 新增使用者

POST /user/
Authorization: Bearer <token>
Content-Type: application/json

{
  "username": "newuser",
  "password": "yourpassword",
  "role": "operator"
}
欄位類型必填說明
usernamestring✓帳號名稱，不可重複
passwordstring✓密碼，以 bcrypt 雜湊儲存
rolestring✓admin / operator / viewer

PUT  /user/<id> — 修改使用者

PUT /user/<user_id>
Authorization: Bearer <token>
Content-Type: application/json

{
  "role": "viewer",
  "password": "newpassword"   // 可選，留空則不修改密碼
}

DELETE /user/<user_id>
Authorization: Bearer <token>
所有 API 也可透過 /apidocs Swagger 介面直接測試，點擊「Authorize」後貼上 Token 即可。

角色與權限

角色說明可存取功能
admin
管理員		 系統最高權限帳號 全部 API、使用者管理（CRUD）、操作紀錄查詢
operator
操作員		 一般操作人員 操作紀錄查詢；不可管理使用者
viewer
檢視者		 唯讀帳號 僅能查看操作紀錄，不可執行任何寫入操作

在程式碼中透過 @require_role() 裝飾器保護端點：

from src.permissions import require_role

@app_user.route('/', methods=['GET'])
@require_role('admin')               # 僅 admin 可存取
def get_users():
    ...

@app_user.route('/', methods=['POST'])
@require_role('admin', 'operator')   # admin 與 operator 均可
def create_user():
    ...

安全機制

Rate Limiting（請求頻率限制）

使用 Flask-Limiter 搭配 Redis 儲存計數，跨多個 Gunicorn Worker 共用限額。

端點限制說明
POST /auth/login10 次 / 分鐘 / IP防止密碼暴力破解
POST /auth/refresh30 次 / 分鐘 / IP防止 Token 刷新濫用
超過限額回傳 429 Too Many Requests。計數器使用 conf/config.ini 中的 Redis 連線設定。

Security Response Headers

所有 API 回應自動加入以下安全標頭：

Header值作用
X-Frame-OptionsDENY防止 Clickjacking（iframe 嵌入攻擊）
X-Content-Type-Optionsnosniff防止 MIME 類型嗅探
X-XSS-Protection1; mode=block舊版瀏覽器 XSS 過濾
Referrer-Policystrict-origin-when-cross-origin控制 Referrer 資訊洩漏

請求大小限制

預設請求 Body 上限為 16 MB（MAX_CONTENT_LENGTH），超過限制 Flask 自動回傳 413 Request Entity Too Large，防止大型 payload DoS 攻擊。

MongoDB 自動建立索引

每次應用程式啟動時（run.py）自動呼叫 ensure_indexes()，確保以下索引存在：

Collection索引說明
usersusername（unique）加速登入查詢，強制帳號唯一
userstemplate_id加速模板篩選查詢
logscreated_at DESC加速紀錄時間排序查詢
logs(username, created_at DESC)加速依使用者篩選紀錄

conf/flask.json — SECRET_KEY

conf/flask.json 存放 Flask 與 JWT 簽名用的 SECRET_KEY，具有以下保護機制：

  • 此檔案已加入 .gitignore，不會被提交至版本控制。
  • 首次啟動 run.py 時若檔案不存在，自動建立並產生 32-byte 隨機金鑰。
  • 正式環境請備份此檔案，或改以 SECRET_KEY 環境變數注入（需修改 conf/config.py）。

部署說明

部署前置：專案目錄與權限

正式伺服器建議將專案放在 /opt/，並將擁有者設為 www-data（Nginx / Gunicorn 執行身份），避免以 root 直接執行。

  1. 將專案移至慣例目錄： 
    sudo mv /root/flask-api /opt/flask-api
  2. 設定目錄擁有者： 
    sudo chown -R www-data:www-data /opt/flask-api
  3. 確認目錄權限（目錄 755，設定檔 644，.env 建議 600）： 
    sudo find /opt/flask-api -type d -exec chmod 755 {} \;
sudo find /opt/flask-api -type f -exec chmod 644 {} \;
sudo chmod 600 /opt/flask-api/.env
若使用 Docker Compose，容器內部以容器自身使用者執行，主機目錄權限只需讓 www-data 可讀取設定掛載目錄（conf/、logs/）即可， 不需對整個專案遞迴 chown。

方式一：本機直接執行（開發用）

  1. 安裝相依套件：pip install -r requirements.txt
  2. 複製設定檔：cp conf/config.ini.default conf/config.ini 並修改資料庫設定。
  3. 複製環境變數：cp .env.default .env。
  4. 啟動服務：python run.py，首次執行自動產生 SECRET_KEY 與預設管理員帳號。
  5. 瀏覽器開啟 http://localhost:5000/admin/。

方式一（正式）：Gunicorn 啟動

正式環境建議改用 Gunicorn 取代 Flask 內建伺服器，以獲得多 Worker 並發與更穩定的錯誤處理。

  1. 完成「方式一」的前三個步驟（安裝套件、複製設定檔、複製 .env）。
  2. （選用）在 conf/config.ini 的 [GUNICORN] 區段調整 Worker 數量、逾時等參數。
  3. 啟動 Gunicorn： 
    gunicorn -c gunicorn.py "run:app"
  4. 背景執行（搭配 systemd 或 supervisor 管理 process 生命週期更佳）： 
    gunicorn -c gunicorn.py "run:app" --daemon
啟動方式適用情境Worker 並發
python run.py本機開發、快速測試單進程（Flask dev server）
gunicorn -c gunicorn.py "run:app"正式環境、主機直接部署多進程（CPU × 2 + 1）
Docker Compose（CMD gunicorn …）容器化部署多進程（同上）
gunicorn.py 位於專案根目錄，所有 Gunicorn 參數均可透過 conf/config.ini 的 [GUNICORN] 區段覆寫，無需修改程式碼。

方式二：Docker Compose（推薦）

  1. 複製設定檔：cp docker-compose.yml.default docker-compose.yml。
  2. 複製並修改 .env、conf/config.ini 與 Nginx 設定（位於 conf/nginx/conf.d/）。
  3. 啟動所有服務：docker compose up -d。
  4. 服務啟動後，Flask App 透過 Nginx 對外服務。
服務名稱說明
nginx反向代理，對外提供 HTTP/HTTPS
appFlask 應用程式（Gunicorn）
mongoMongoDB
mysqlMySQL
redisRedis

Nginx 模式選擇

NGINX_MODE設定檔適用情境
httpdefault.conf.http.template本機開發、無 SSL 測試環境
cloudflaredefault.conf.cloudflare.template使用 Cloudflare 代理（需放入 Cloudflare 憑證）

方式三：主機 Nginx（不使用容器 Nginx）

若伺服器已安裝 Nginx，或不希望讓 Nginx 跑在 Docker 容器內，可以讓 Docker Compose 只啟動 app / mongo / mysql / redis，由主機的 Nginx 直接反向代理 Flask。 對應設定檔位於 conf/nginx/host/，依 SSL 需求選擇其中一份複製使用。

前置步驟
  1. 修改 docker-compose.yml，在 app 服務加上 ports， 將 Flask 綁定到主機的 127.0.0.1:5000： 
    app:
  ports:
    - "127.0.0.1:5000:5000"   # 只允許本機 Nginx 連入，不對外暴露
  2. 啟動 App 與資料庫（略過 nginx 服務）： 
    docker compose up -d app mongo mysql redis
  3. 確認 Flask 已啟動：curl http://127.0.0.1:5000/health（回傳 ok）。
  4. 依下方模式選擇複製對應 Nginx 設定檔。
模式 A — 純 HTTP

適用：本機開發、IP 直連、或由 Cloudflare 在外層處理 HTTPS。

  1. 複製設定檔並替換域名： 
    sudo cp conf/nginx/host/http.conf /etc/nginx/sites-available/flask-app
sudo sed -i 's/YOUR_DOMAIN/example.com/g' /etc/nginx/sites-available/flask-app
  2. 啟用設定並重載： 
    sudo ln -s /etc/nginx/sites-available/flask-app /etc/nginx/sites-enabled/flask-app
sudo nginx -t && sudo systemctl reload nginx
模式 B — Cloudflare SSL（Origin CA）

適用：域名透過 Cloudflare Proxy，SSL/TLS 模式設為 Full (Strict)。

  1. 在 Cloudflare Dashboard → SSL/TLS → Origin Server → Create Certificate 取得憑證。
  2. 將憑證寫入伺服器： 
    sudo mkdir -p /etc/ssl/cloudflare
sudo nano /etc/ssl/cloudflare/origin.pem   # 貼上 Origin Certificate
sudo nano /etc/ssl/cloudflare/origin.key   # 貼上 Private Key
sudo chmod 600 /etc/ssl/cloudflare/origin.key
  3. 複製設定檔並替換域名： 
    sudo cp conf/nginx/host/cloudflare.conf /etc/nginx/sites-available/flask-app
sudo sed -i 's/YOUR_DOMAIN/example.com/g' /etc/nginx/sites-available/flask-app
  4. 啟用設定並重載： 
    sudo ln -s /etc/nginx/sites-available/flask-app /etc/nginx/sites-enabled/flask-app
sudo nginx -t && sudo systemctl reload nginx
模式 C — Let's Encrypt SSL

適用：伺服器直接暴露網際網路，使用 Certbot 自動申請免費憑證。

  1. 安裝 Certbot： 
    sudo apt install -y certbot python3-certbot-nginx
  2. 先用模式 A（http.conf）讓 Nginx 跑起來，再申請憑證： 
    sudo certbot --nginx -d example.com
    Certbot 會自動修改 /etc/nginx/sites-available/flask-app 加入 SSL 設定。
    若偏好手動控制，改用 webroot 方式： sudo certbot certonly --webroot -w /var/www/certbot -d example.com， 再手動複製 conf/nginx/host/https-letsencrypt.conf。
  3. 憑證路徑（自動申請後）： 
    /etc/letsencrypt/live/example.com/fullchain.pem
/etc/letsencrypt/live/example.com/privkey.pem
  4. 設定自動續約（Certbot 安裝時通常已建立 systemd timer，確認即可）： 
    sudo systemctl status certbot.timer
模式設定檔來源SSL 憑證位置
A — HTTPconf/nginx/host/http.conf無
B — Cloudflareconf/nginx/host/cloudflare.conf/etc/ssl/cloudflare/
C — Let's Encryptconf/nginx/host/https-letsencrypt.conf/etc/letsencrypt/live/<domain>/
主機 Nginx 與容器 Nginx 不可同時啟用，兩者都監聽 port 80/443 會衝突。 請確認 docker-compose.yml 的 nginx 服務未被啟動（docker compose ps 確認）。
